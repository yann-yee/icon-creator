# 图标 Icon 设计（用户体验 / 认知 / 交互导向）设计指南

> 来源：从原始 Icon 设计指南资料整理，并已内化为本 skill 的参考手册。

**文档类型**：正式设计规范指南

**核心定位**：以用户认知、识别效率、交互体验为第一准则，兼顾视觉规范、落地约束、正反案例、场景边界，适用于 UI、产品、视觉设计团队执行参考

**适用范围**：移动端、桌面端、Web 端、B 端 / C 端、软硬件界面图标设计

---

## 一、整体设计总纲 & 核心约束规则

### 1.1 顶层设计理念

图标是可视化交互语言，优先级排序：**识别易懂 > 交互顺手 > 视觉美观 > 创意个性**。

所有设计动作必须围绕「降低用户认知成本、减少思考时间、降低误操作率」展开。

### 1.2 五大强制约束（全员必遵守）

1. **语义唯一约束**：一个图标仅对应一个功能 / 状态，禁止一图多义。
2. **符号通用约束**：高频功能必须使用行业通用符号，禁止自创小众隐喻符号。
3. **视觉统一约束**：同项目 / 同模块图标，网格、描边、圆角、风格、色彩体系完全统一。
4. **交互热区约束**：触控类图标严格遵循最小点击区域标准，视觉尺寸 ≠ 点击热区。
5. **无障碍约束**：图标与背景对比度、线条粗细、色彩语义必须兼容弱视觉、暗光场景。

### 1.3 适用人群与场景划分

| 用户 / 产品类型 | 整体设计倾向 | 核心约束 |
|----------------|-------------|----------|
| 通用 C 端（APP / 网页） | 造型圆润、表意直白、亲和力强 | 优先大众认知，弱化小众设计 |
| B 端工具 / 后台 / 系统 | 几何简约、线条利落、克制专业 | 减少装饰，突出功能识别 |
| 老年 / 低视力群体 | 线条加粗、图形放大、细节简化 | 禁用细线条、低对比色、复杂轮廓 |
| 儿童向产品 | 轮廓饱满、造型童趣、色彩明快 | 符号仍需通用，不做过度抽象变形 |
| 海外 / 多语言产品 | 纯图形无地域文化隐喻 | 规避宗教、地域特殊符号 |

## 二、图标语义与认知设计（核心：让用户一眼看懂）

### 2.1 符号选用规范 & 正反案例

#### 2.1.1 优先使用「全球通用标准符号」

主流通用符号清单（强制沿用，禁止大幅篡改）：

| 功能 | 标准符号 |
|------|---------|
| 搜索 | 放大镜 |
| 设置 / 系统 | 齿轮 |
| 返回 / 上一级 | 向左箭头 |
| 关闭 / 退出 | 叉号 |
| 菜单 | 三条横线（汉堡图标） |
| 下载 | 向下箭头 + 容器 |
| 分享 | 向外发散箭头 / 三点连线 |

- ✅ **正面示例**：标准放大镜图标，轮廓经典、无多余变形，任意用户第一眼可识别为「搜索」。
- ❌ **反面示例**：把放大镜手柄加长、镜片改成异形、叠加花纹；或用抽象曲线替代放大镜。问题：打破用户固有认知，增加理解成本，新用户极易看不懂。

#### 2.1.2 表意规则：简洁直观，拒绝过度隐喻

- 功能类图标：具象优先，用实物外形表达功能；
- 分类 / 标签类图标：可轻度抽象，但轮廓特征必须清晰；
- **严禁**：用多层隐喻、故事化图形表达基础操作功能。

- ✅ **正面示例**：「删除」使用标准垃圾桶图形，形态简化但特征保留，认知零门槛。
- ❌ **反面示例**：用破碎纸张、火焰、复杂手绘图案表示删除。问题：隐喻过重，不同用户产生不同解读，识别效率大幅下降。

#### 2.1.3 图形区分约束：相似功能强差异化

功能相近、位置相邻的图标，必须在轮廓、结构、视觉重心上做出明显区分，禁止造型趋同。

- ✅ **正面示例**：「返回」←、「关闭」×、「收起」↑ 三者轮廓差异大，并排摆放也不会混淆。
- ❌ **反面示例**：返回箭头、前进箭头仅方向不同，整体轮廓几乎一致；编辑、修改图标外形高度相似。问题：视觉混淆，高频出现误点击。

### 2.2 图文搭配强制规则（落地约束）

根据使用频次、用户熟悉度，强制区分展示形式：

- **高频通用功能（搜索、返回、设置）**：可纯图标展示；导航栏、工具栏常规使用。
- **低频功能、业务专属功能**：强制要求：图标 + 文字标签组合，不允许单独放图标。
- **底部导航、侧边主导航**：统一采用「图标 + 文字」标配，降低新手学习成本。

- ✅ **正面示例**：后台「数据报表」（低频业务功能）：图标 + "数据报表" 文字同行展示。
- ❌ **反面示例**：复杂后台内，仅用抽象图形代表「报表、日志、权限」，无任何文字说明。问题：新用户必须逐个点击试探，使用体验极差。

### 2.3 跨文化内容约束（国际化必看）

- 禁止使用带有地域习俗、宗教、政治指向的图形；
- 手势、动物、花卉等图形，在海外场景谨慎使用；
- 纯线条、几何、工具类符号全球通用性最强，优先选用。

- ❌ **反面示例**：用特定地域手势、本土民俗图案作为通用功能图标，海外用户无法理解。

## 三、视觉体系规范（统一感知，固定约束参数）

### 3.1 基础网格与尺寸约束（硬性参数）

#### 3.1.1 标准网格规范

- 移动端 / 主流 UI：**24dp** 基础网格（行业通用强制标准）
- 大图标 / 引导图标：32dp、40dp 网格，同项目网格体系统一
- **约束**：所有图标必须在网格内绘制，图形不超网格边界、不严重偏小。

#### 3.1.2 内边距（安全留白）约束

网格与图形之间保留固定留白，保证视觉呼吸感，避免拥挤 / 空洞。

- ✅ **正面**：图形居中，四周留白均匀，整体舒展。
- ❌ **反面**：图形顶满网格边界、或图形过小四周大面积留白，视觉失衡。

#### 3.1.3 交互点击热区（核心交互约束）

**视觉尺寸 ≠ 点击热区，此为强制红线**

- **移动端（手机 / 平板 触控操作）**：最小可点击热区 **44dp × 44dp**。规则：图标视觉图形可小于 44dp，但透明热区必须铺满 44dp 区域。
- **桌面端（鼠标操作）**：最小点击区域 32px，要求轮廓清晰，hover 状态变化明显。

- ✅ **正面示例**：图标图形 24dp，外层热区扩展至 44dp，手指点击边缘也可正常触发。
- ❌ **反面示例**：图标图形 24dp，点击区域仅和图形一致，手指稍偏就点击失效，频繁误触。

### 3.2 线条、圆角、造型约束（整套统一）

#### 3.2.1 描边粗细约束

- 同项目所有线性图标，描边数值完全一致，禁止粗细混搭；
- 常规 UI 图标：描边 2px / 1.5px 二选一，选定后全局沿用；
- 面向老年 / 低视力用户：描边至少加粗至 2.5px。

- ✅ **正面示例**：整套导航、工具图标，全部使用 2px 均匀线条，视觉风格统一。
- ❌ **反面示例**：一部分图标细线条、一部分粗线条，页面视觉杂乱，破坏整体感知。

#### 3.2.2 转角 / 圆角约束

全局统一转角规则，三选一，不可混用：

- 全直角
- 统一小圆角（2px/3px）
- 大圆角（圆润风格）

- ✅ **正面**：所有图标转角圆角半径一致，风格协调。
- ❌ **反面**：有的直角、有的大圆角、有的小圆角，风格割裂。

#### 3.2.3 视觉重量平衡约束

圆形、方形、长条形、不规则图形，做到视觉体量均等。

- 细长图形适当放大视觉占比；
- 实心面状图形适当收缩，避免视觉过重。

- ✅ **正面**：圆形图标、方形图标、箭头图标，视觉上大小观感一致。
- ❌ **反面**：圆形图标显大，细长箭头图标显小，页面参差不齐。

### 3.3 风格强制约束（五选一，禁止混搭）

项目启动前确定唯一风格，全程严格执行：

1. 纯线性图标
2. 纯面性（实心）图标
3. 线面结合图标
4. 简约渐变图标（仅装饰类可用）
5. 极简手绘图标（娱乐 / 童趣产品专用）

- ❌ **严重反面案例**：页面内同时出现线性图标 + 面性图标 + 渐变立体图标。问题：视觉体系彻底混乱，用户视觉负担极大。

### 3.4 色彩规范 & 无障碍约束

#### 3.4.1 色彩语义规则（固定含义，不可篡改）

| 状态 | 色彩 |
|------|------|
| 常规功能图标 | 中性灰、深灰、黑色（主文本色） |
| 成功 / 完成 | 绿色系 |
| 警告 / 提醒 | 黄色 / 橙色系 |
| 错误 / 禁止 / 删除 | 红色系 |
| 选中 / 激活 | 品牌主色 |

- ✅ **正面**：统一沿用行业色彩语义，用户凭颜色即可快速判断状态。
- ❌ **反面**：用红色表示 "完成"、绿色表示 "警告"，违背大众认知，极易误导用户。

#### 3.4.2 对比度无障碍约束（硬性要求）

图标与背景色对比度，必须满足：

- 常规界面：对比度 ≥ 4.5:1
- 大尺寸图标：对比度 ≥ 3:1
- 暗光模式、深色模式下，重新校验对比度，禁止浅灰 + 深灰低对比搭配。

- ❌ **反面案例**：浅灰色图标置于浅白色背景，强光 / 弱光下都难以分辨轮廓。

#### 3.4.3 特效使用约束

- **核心功能图标**：禁止使用复杂渐变、多层阴影、描边外发光、纹理；
- **装饰类图标**：可轻度使用渐变，但不能影响轮廓识别。

- ❌ **反面**：操作图标叠加立体阴影、炫彩渐变，轮廓被弱化，识别变慢。

## 四、图标分类、场景用法 & 场景约束

按功能划分四大类，每类明确设计要求、使用约束、正反案例。

### 4.1 功能操作类图标（高频交互：返回、搜索、编辑、删除等）

- **使用位置**：顶部栏、工具栏、按钮、悬浮操作区
- **强制约束**：符号必须选用通用标准图形；线条加粗、轮廓简化，保证极速识别；触控区域严格达标，优先保障操作流畅。
- ✅ **正面**：标准返回箭头、标准搜索放大镜，造型极简，点击区域充足。
- ❌ **反面**：功能图标增加多余装饰、造型扭曲，点击区域过小。

### 4.2 导航类图标（页面跳转：底部导航、侧边栏、分类）

- **使用位置**：主导航、标签栏、分类入口
- **强制约束**：标配「图标 + 文字」，不建议纯图标导航；选中 / 未选中状态差异明显（颜色、填充、透明度变化）；同导航栏风格、尺寸、描边完全统一。
- ✅ **正面**：未选中灰色线性，选中品牌色面性，状态一目了然。
- ❌ **反面**：选中与未选中视觉差异极小，用户无法分辨当前所在页面。

### 4.3 状态提示类图标（加载、成功、报错、空数据、权限）

- **使用位置**：弹窗、空页面、表单反馈、操作结果
- **强制约束**：图形 + 色彩双重传递状态信息；不同状态图形必须强区分，禁止外形近似；尺寸略大于常规功能图标，保证醒目。
- ✅ **正面**：对勾 = 成功、感叹号 = 警告、叉号 = 失败，图形 + 标准色组合。
- ❌ **反面**：成功、警告、错误使用外形相似的圆形图标，仅靠细微颜色区分。

### 4.4 装饰 / 标签类图标（分类标签、点缀、头像配饰）

- **使用位置**：卡片标签、标签栏、页面点缀、趣味标识
- **强制约束**：视觉权重弱化，尺寸小于功能图标；不能抢夺主体内容视线；可适度创意，但轮廓仍需清晰。
- ✅ **正面**：小尺寸简约图形作为分类标签，辅助表达，不抢眼。
- ❌ **反面**：装饰图标尺寸过大、色彩艳丽，盖过正文内容。

## 五、输出规范、文件约束 & 落地要求

### 5.1 格式与尺寸输出约束

- Web/UI 界面：优先输出 SVG 矢量图（无损缩放，适配多端）
- 移动端 APP：输出多倍率 PNG（@1x / @2x / @3x），透明底色
- 桌面图标 / 网页 Favicon：输出标准 ICO 格式，包含 16px/32px/48px 多尺寸
- **统一约束**：所有图标白底 / 透明底统一，禁止部分白底、部分透明底混用。

### 5.2 命名规范约束（统一规则，方便协作）

- **命名格式**：`模块-功能-状态-尺寸`
- **示例**：`toolbar-search-normal-24dp`、`nav-home-active-24dp`
- **禁止**：中文命名、随意乱命名、拼音简写混乱。

## 六、用户测试流程 & 验收标准（上线前必做）

### 6.1 三项基础测试（验收必过）

1. **快速识别测试**：随机展示图标（0.5~1 秒），普通用户可准确说出对应功能，识别率低于 90% 必须返工。
2. **多场景显示测试**：强光、暗光、深色模式、不同分辨率设备下，图标轮廓清晰、无模糊、无裁切。
3. **交互测试**：移动端边缘点击、多指误触场景测试，热区触发正常，无点击失灵。

### 6.2 A/B 测试（重要功能可选）

同一功能制作 2 套方案，对比：识别速度、误触率、用户偏好，择优上线。

### 6.3 验收不通过判定（直接返工）

出现以下任意一条，图标不予上线：

- 语义模糊，超过 30% 用户看不懂；
- 点击热区不达标，存在大面积点击失灵；
- 同页面风格、线条、圆角混乱不统一；
- 色彩对比度不满足无障碍标准；
- 相似图标造型趋同，极易混淆。

## 七、高频问题 & 避坑清单（反面问题汇总）

| 问题 | 整改 |
|------|------|
| ❌ 过度追求艺术创意，符号晦涩难懂 | 回归通用标准符号 |
| ❌ 整套图标描边、圆角、风格混搭 | 统一视觉参数与风格 |
| ❌ 移动端图标视觉正常，点击热区过小 | 扩展透明交互区域至 44dp |
| ❌ 低频业务功能只放图标、不配文字 | 强制增加文字标签 |
| ❌ 相近功能图标外形高度相似 | 强化轮廓差异 |
| ❌ 功能图标叠加渐变、立体、复杂特效 | 移除特效，简化轮廓 |
| ❌ 色彩违背通用状态语义（红 = 完成、绿 = 报错） | 沿用标准色彩语义 |
| ❌ 低对比度配色，暗光下看不清 | 提升色彩对比度至规范值 |
