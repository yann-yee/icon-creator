# Positive / Negative Examples — 正反案例与修正策略

本手册用于强化设计判断。每个案例都包含：好做法、坏做法、为什么、如何修正。

## 1. Logo 正反案例

### 1.1 概念数量

✅ 正例：

> 一个云存储品牌，用“云轮廓 + 中央负形上箭头”表达上传与同步。

原因：一个主隐喻，两个概念自然融合。

❌ 反例：

> 同时画云、锁、闪电、地球、用户头像和 AI 星光。

问题：概念堆叠，记忆点消失，小尺寸不可读。

修正：只保留“云 + 锁”或“云 + 箭头”，其他概念交给文案表达。

### 1.2 行业通用符号

✅ 正例：

> 金融品牌不直接画硬币，而使用稳定的几何柱体和向上切角，暗示增长与可信。

❌ 反例：

> 金融品牌直接使用美元符号、柱状图和金币。

问题：模板化强，品牌差异弱。

修正：从品牌名、服务模式、目标用户中提取专属图形，而不是复制行业符号。

### 1.3 单色可用性

✅ 正例：

> 彩色版有渐变，但去掉渐变后仍靠轮廓和负形成立。

❌ 反例：

> Logo 的识别完全依赖蓝紫渐变和阴影，高对比单色下变成普通圆形。

修正：先设计黑白版，再上色。

## 2. App Icon 正反案例

### 2.1 背板关系

✅ 正例：

> 主体图形占安全区域 62% 左右，背板颜色提供清晰对比，圆角裁切后仍居中。

❌ 反例：

> 把完整横版 logo 放进圆角方形中，文字在手机桌面上不可读。

修正：提取 logo 的最小符号，不把完整字标塞进 app icon。

### 2.2 细节密度

✅ 正例：

> 用 2–3 个大形体表达核心功能，细节仅服务识别。

❌ 反例：

> 在 512 画板中加入纹理、长文字、小徽章、多层光效。

问题：512 看起来丰富，48px 变成噪点。

修正：按 64px、48px、32px 逐级缩小预览，删掉无法识别的细节。

### 2.3 平台裁切

✅ 正例：

> 主体距离画板边缘至少 48–64px，关键轮廓不贴边。

❌ 反例：

> 主体充满画板，圆角裁切后被削掉。

修正：增加内边距，使用视觉安全区。

## 3. Functional Icon Set 正反案例

### 3.1 风格统一

✅ 正例：

> 搜索、设置、消息、用户全部使用 24px 等效线宽、圆角端点、同样的开放路径比例。

❌ 反例：

> 搜索是线性，设置是实心，消息是渐变，用户是卡通。

修正：先定义图标系统参数，再逐个绘制。

### 3.2 语义清晰

✅ 正例：

> 删除使用垃圾桶，编辑使用铅笔，搜索使用放大镜。

❌ 反例：

> 用抽象几何符号表达“设置”，用户必须学习才能理解。

修正：功能图标优先服从语义，不要过度追求品牌化。

### 3.3 视觉重量

✅ 正例：

> 圆形图标略放大，方形图标略缩小，保证视觉重量一致。

❌ 反例：

> 所有图标机械占满同一边界框，导致圆形显小、方形显重。

修正：使用光学补偿，而不是只看几何边界。

## 4. SVG 生产正反案例

### 4.1 画板

✅ 正例：

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="512" height="512" viewBox="0 0 512 512" shape-rendering="geometricPrecision">
```

❌ 反例：

```xml
<svg width="24" height="24" viewBox="0 0 24 24">
```

问题：不符合本 skill 的统一源画板，后续导出和质量检查不一致。

修正：在 512 画板中重新映射坐标。

### 4.2 位图嵌入

✅ 正例：

```xml
<path fill="#111" d="M128 256 ..."/>
```

❌ 反例：

```xml
<image href="data:image/png;base64,..."/>
```

问题：无法无损缩放，也不符合 CLI 检查。

修正：重绘为 path / circle / rect / polygon。

### 4.3 正式变体

✅ 正例：

```bash
svg2icon --svg logo.svg --variants primary,mono,reversed
```

❌ 反例：

```bash
svg2icon --svg logo.svg --invert
```

问题：负片不是品牌反白版本，会产生不可控颜色。

修正：使用 `mono` 和 `reversed` 正式变体。

## 5. 高频反模式清单

| 反模式 | 典型表现 | 修正 |
|---|---|---|
| 概念堆叠 | 一个图标塞入 4+ 个隐喻 | 限制为 1 个主隐喻 |
| 渐变依赖 | 去掉渐变就不可识别 | 先设计单色轮廓 |
| 文字依赖 | 小尺寸需要读字 | 提取字母或符号 |
| 模板化 | 像素材库图标 | 加入品牌专属记忆点 |
| 风格混搭 | 同一套图标线宽/填充/圆角不统一 | 先定义系统参数 |
| 过度拟物 | 光影纹理过多 | 压缩为 2–3 个层级 |
| 忽略反白 | 深色背景不可用 | 生成 reversed 测试 |
| SVG 不自包含 | 引外部字体/图片 | 全部转 path / inline defs |

## 6. 返工判断

出现以下任一情况，应返工而不是微调：

- 16px 下主符号完全不可读。
- 单色后失去识别性。
- 与知名竞品高度相似。
- 需要解释超过一句话才能理解。
- 图标组中有明显来自不同风格库的感觉。
