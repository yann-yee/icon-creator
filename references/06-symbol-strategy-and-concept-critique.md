# Symbol Strategy & Concept Critique

本参考用于把 Product Meaning 转化为可拥有、可识别、可生产的视觉概念。

核心原则：**先选语义领地，再选符号；先判断概念，再画几何。**

---

# 1. Symbol Territories

Symbol Territory 是一组与产品含义相关的语义空间，不是具体图标。

例如一个“自动发现并纳入网络拓扑”的功能：

```text
Discovery — revealing the unknown
Emergence — something becoming visible
Joining — a new node entering a system
Topology — relationships and placement
Awareness — system gaining knowledge
```

这些 territory 比“雷达 + 设备”提供更宽但仍有边界的设计空间。

建议产生 2–4 个 territory；太多会稀释方向。

---

# 2. Abstraction Levels

## LITERAL

直接描绘对象/动作。

适合：Functional Icon、高频操作。

风险：品牌独特性低。

## METONYMIC

用相关概念代表整体。

例如“恢复”不画硬盘，而画“回到稳定状态”的关系。

适合：App Icon、产品 feature symbol。

## ABSTRACT

通过形态表达底层概念，如秩序、连接、聚合、连续。

适合：Brand Mark。

风险：如果没有 product connection，会变成装饰几何。

## LETTERFORM

基于名称/首字母构造。

优点：ownability 强。
风险：可能只表达名字，不表达产品人格。

## HYBRID

最多组合两个逻辑，并明确一个主导概念。

禁止：

```text
云 + 盾牌 + 闪电 + AI sparkle + 首字母
```

这种“关键词拼贴”。

---

# 3. Concept Generation

好的候选应该在核心 idea 上明显不同，而不是只换颜色。

每个 concept 用下面格式：

```markdown
## Concept — [Name]

Core idea:
...

Product connection:
...

Aesthetic connection:
...

Territory:
...

Abstraction level:
...

Visual anchor:
...

Ownability:
...

Small-size behavior:
...

Primary risk / likely misreading:
...
```

概念数量默认 2–3 个即可。

---

# 4. Concept Critique

不要只做 1–5 分总分矩阵。评分容易偏向“每项都还行”的平庸方案。

按下面顺序 critique。

## 4.1 Product Specificity

问：

> 把品牌名去掉，这个概念为什么仍然和该产品有关？

如果只能回答“因为这是科技产品”，则不够具体。

## 4.2 Aesthetic Integrity

是否真正体现 Aesthetic Thesis？

例如 thesis 是 `Powerful × Quiet`，但概念靠强霓虹、尖刺和多层发光表达“力量”，则已经失衡。

## 4.3 Ownability

问：

- 竞争对手能否原样拿走？
- 视觉锚点是否足够明确？
- 是否只是常见行业 pictogram？

Ownability 不等于奇怪。

## 4.4 Misreading Risk

必须主动寻找最可能错误理解：

```text
像上传？
像加密货币？
像医疗？
像电源？
像游戏公会？
像已有大品牌？
```

## 4.5 Small-size Survival

缩小后：

- 哪个特征仍然存在？
- 哪个意义会消失？
- 是否依赖负形细节？

如果 concept 的全部价值只在 512px 才能看见，它不适合 App Icon / favicon。

## 4.6 Mono Survival

去掉颜色/渐变后是否仍成立？

颜色可以增强 concept，不能替代 concept。

# 5. Asset-specific Strategy

## Logo

推荐探索：

- abstract transformation
- distinctive negative space
- controlled letterform
- unique relational geometry

不推荐默认使用：

- 行业通用对象作为完整答案
- 多层故事隐喻
- 依赖当前趋势的特效

## App Icon

重点：

- launcher silhouette
- one dominant visual anchor
- strong foreground/background relationship
- safe area / crop behavior
- fast recognition

允许比 Logo 更直观，但仍需有产品归属。

## Functional Icon

优先：

- convention
- semantic clarity
- family consistency
- adjacent differentiation

不要为了品牌独特性改坏通用符号。

---

# 6. Familiar × Distinctive Balance

可用这个模型判断创新程度：

```text
Known semantic skeleton
        +
One product-specific transformation
        =
Recognizable but ownable
```

例如搜索图标不需要重新发明放大镜；但一个产品的“智能搜索”状态变化可以通过 surrounding state、motion 或 secondary treatment 表达，而不是扭曲放大镜本身。

---

# 7. Negative Space

负形是高价值手段，但不是自动加分项。

使用条件：

- 主轮廓本身成立；
- secondary meaning 与产品真实相关；
- 小尺寸不破坏主识别；
- 不需要长篇解释才能发现。

如果隐藏符号成为唯一设计理由，通常说明 concept 太弱。

---

# 8. Similarity / Cliché Audit

在定稿前检查：

- 是否落入 AI sparkle / neural network / brain；
- cloud + arrow；
- shield + check；
- hexagon + nodes；
- rocket + growth；
- generic infinity / loop；
- gradient blob；
- random letter inside rounded square。

这些不是绝对禁止，而是需要更强的 product-specific rationale。

问：

> 如果必须使用这个 archetype，我们做了什么真正来自产品机制的改变？

---

# 9. Concept Selection

选择 strongest concept 时优先级：

```text
Product truth
→ Aesthetic integrity
→ Semantic clarity appropriate to asset type
→ Ownability
→ Context performance
→ Production simplicity
```

不要让“容易画 SVG”决定设计。

---

# 10. Replan Signals

出现以下情况回到 Product Meaning / Aesthetic Thesis：

- 所有 concept 都像同类模板；
- 每个 concept 只是同一个 object 的不同造型；
- 无法解释与 Differentiator 的关系；
- 只能依赖 style tag 区分概念；
- user feedback 指向人格/含义错误，而非表面细节；
- 真正产品 context 与概念冲突。

不要通过继续加装饰修复一个错误的 symbol strategy。
